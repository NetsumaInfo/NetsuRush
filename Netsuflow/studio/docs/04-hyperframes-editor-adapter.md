# HyperFrames editor adapter

## Decision

NetsuFlow Studio uses HyperFrames as an authoring engine, not as the application
shell. The integration has three layers with different stability expectations.

| Layer | Preferred use | Dependency policy |
|---|---|---|
| `@hyperframes/sdk` | source model, mutations, patches, overrides | foundational, pinned |
| `@hyperframes/player` | isolated playback and seek | foundational, pinned |
| `@hyperframes/studio` | timeline/preview/source UI building blocks | selective, wrapped, replaceable |
| `@hyperframes/studio-server` | source mutation, project/preview/render backend helpers | selective, worker-only |

This follows the vendor's own integration guidance. [ST-HF-OVERVIEW]
[ST-HF-STUDIO] [ST-HF-STUDIO-SERVER]

## What is not adopted

- `StudioApp` as the visible NetsuRush module.
- HyperFrames routing, global shell, navigation, dialogs, or theme as product UI.
- Direct Studio component access to arbitrary project paths.
- Direct iframe writes to the filesystem.
- Undocumented internal import paths.
- Automatic dependency upgrades without export and behavior tests.

## SDK session

The adapter opens source through `openComposition()` and owns its lifecycle.

```ts
const composition = await openComposition(baseHtml, {
  preview,
  overrides: storedOverrides,
  history: false,
});
```

Host-owned history is required because NetsuFlow must coordinate visual edits,
code edits, agent proposals, file watcher changes, and Resolve publishing.
HyperFrames patch/inverse-patch events are recorded inside a NetsuFlow change
set. [ST-HF-OVERRIDES]

## Supported edit operations

The first adapter supports only operations with explicit source meaning:

- set text;
- set/remove an attribute;
- set supported inline styles;
- update declared composition variables;
- update clip `data-start`, `data-duration`, `data-track-index`,
  `data-media-start`, and `data-volume`;
- insert known video, audio, image, text, and nested-composition templates;
- remove an element with a stable `data-hf-id`;
- serialize or store sparse overrides.

The SDK already exposes stable identities and typed mutations for part of this
surface. Timing/source mutations that require Studio server helpers stay behind
the adapter. [ST-HF-SDK-EDIT] [ST-HF-TIMELINE]

## Capability classification

When a composition opens, the adapter produces a capability report:

```json
{
  "preview": true,
  "code": true,
  "variables": true,
  "elementSelection": true,
  "canvasTransform": false,
  "clipTimeline": true,
  "keyframes": false,
  "reasons": {
    "canvasTransform": "selected element has no supported source affordance",
    "keyframes": "animation is generated by dynamic JavaScript"
  }
}
```

Unknown source patterns remain previewable and editable as code. The adapter
must never rewrite a dynamic block merely because it visually resembles a
supported primitive.

## Studio component adoption gate

Each candidate component is evaluated independently:

| Component | First question | Fallback |
|---|---|---|
| `NLEPreview` | Can NetsuFlow own selection and styling? | Player + custom overlay |
| `Timeline` | Can it edit external project state through callbacks? | custom clip timeline |
| `SourceEditor` | Can it support HTML now and TSX later? | engine-neutral code editor shell |
| `PropertyPanel` | Can controls use NetsuRush design components? | custom inspector over SDK operations |
| `FileTree` | Can it merge project and virtual sources safely? | custom project explorer |

No decision is made from appearance alone. T01 measures API coupling,
keyboard behavior, state ownership, bundle cost, and runtime stability.

## Preview and code synchronization

1. The source editor produces a complete source snapshot or bounded text edits.
2. The core validates the base revision.
3. The adapter parses/opens the new source.
4. A successful session replaces the preview atomically.
5. A failed source remains in the editor with diagnostics while the last valid
   preview stays visible and clearly marked stale.
6. The playhead is restored when the new duration still contains that frame;
   otherwise it is clamped.

Debouncing is allowed for preview work, never for explicit save.

## Variables and Fusion parameters

HyperFrames declared variables drive the Studio inspector. The same stable
variable IDs can map to the fixed OpenFX control bank already designed for
Fusion. [ST-HF-VARIABLES] [ST-NF-OFX]

Studio defaults and per-project values are separate from per-instance Fusion
keyframes:

```text
composition default
  <- Studio project override
     <- OpenFX instance control at frame time
```

The final value and its revision/hash must enter every preview and frame cache
key.

## Version policy

- Pin exact HyperFrames package versions in the editor worker.
- Freeze public export/type fingerprints for every adopted package.
- Run T01 before upgrading.
- Keep Studio package imports in one engine-specific wrapper directory.
- Record repository license plus resolved package tarball licenses.
- Never let Studio package changes require an OpenFX binary update.
