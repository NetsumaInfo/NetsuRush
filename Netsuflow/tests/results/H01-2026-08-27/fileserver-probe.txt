Conclusion: two independent failures against NetsuFlow's requirements.

1. Bind. serve({ fetch, port }) is called with no hostname, so @hono/node-server
   binds every interface. The project directory was reachable from this machine's
   LAN address. FileServerOptions exposes no hostname, so configuration cannot
   narrow it.

2. Root escape. Hono normalises the ordinary traversal forms; six of seven
   attempts returned 404. The surviving form decodes to a backslash after
   normalisation, and path.join treats that as a separator on Windows, so
   join(projectDir, relativePath) resolves above the root. There is no canonical
   root check to catch it.

NetsuFlow does not inherit either failure: createFileServer is exported but never
called inside the engine, and createCaptureSession takes a caller-supplied URL.
Decision: do not adopt; write the project server as Task 3 already planned, with
these cases as named regression tests. Report both upstream.
