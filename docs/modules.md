## Reference board (`src/components/reference/`)

Infinite canvas (pan/zoom) where images, local videos and YouTube videos are laid out like a mood board. The idea and the interaction model are inspired by [AnimRef](https://github.com/lettucegoblin/AnimRef); the implementation is independent — React with native pointer events, rather than its vanilla JS and interact.js.

- **Geometry is in WORLD coordinates**, displayed through a `transform: translate()/scale()` layer. `referenceShared.ts` holds the `BoardItem` model and helpers. `ref` is the **persisted** locator (disk path, remote URL, YouTube id); `src` is the display URL **recomputed on load** by `displaySrc` — an objectURL/blob does not survive a reload.
- **Gestures are native pointer events** (`usePointerTransform.ts`), not interact.js: move, resize (8 handles, locked ratio, local frame when rotated), rotate (15° snap with Shift). During a gesture the geometry lives in **local** state coalesced in rAF, so only the manipulated item re-renders; commit to the store on `pointerup`. `BoardItem` is `memo`, so panning does not re-render items.
- **YouTube plays through a plain `<video>`, not the embedded player**: the embedded player repaints its chrome (big play button, end screen) on every seek and pause, which flashed on each loop — no `playerVars` removes it. `core/ytstream.js` resolves the stream URL with yt-dlp and relays it on `/ytstream?id=`, so the board reads it like any local video: same loop, ping-pong, trim and playhead. The relay renews the URL itself on a 403 (YouTube's URLs expire), which keeps `/ytstream?id=` a stable, persistable source. The format selector only accepts `protocol^=https` and prefers `avc1` capped at 1080p: WebView2 has no native HLS (YouTube's "Premium 1080p" itag 616 exists only as an m3u8 manifest), and a 4K VP9/AV1 stream falls back to software decoding — both end as a dead `<video>`. The same cap applies to downloads (`core/extract.js`), where a 4K AV1 file also weighs a hundred times a usable 1080p H.264. Reaching inside the iframe as AnimRef does (`contentDocument`, `--disable-site-isolation-trials`) is **not an option here**: those flags are process-wide, and `/media`+`/stream` serve arbitrary disk files relying on the browser's same-origin refusal.
- Packaged NetsuBoard always provisions and verifies `yt-dlp` plus `gallery-dl`; they are Board runtime requirements, not optional module dependencies. A runtime-schema bump sends older incomplete installs through the normal repair flow.
- **yt-dlp refreshes with the application.** It is the one runtime item that rots — the platforms break its extractors every few weeks, while ffmpeg, the shaders and the weights keep working for years — and the pin in `python/requirements-reference.txt` froze the venv on the day of the install. `core/ytdlpUpdate.js` runs `pip install --upgrade yt-dlp[default,curl-cffi]` on the **first boot of a new application version**, in the background, from `onListening`. The pin stays the floor for a fresh install and for a repair; this only carries an existing venv between two releases, and pip's default `only-if-needed` strategy keeps the torch/CUDA stack of the same venv out of it. The version checked is recorded as `ytDlpCheckedFor` in `nr.config.json`, and a **failure writes no marker**, so someone offline the day they updated gets the refresh at the next boot instead of losing it. NetsuBoard runs the same policy on its standalone binary, with `yt-dlp -U`.
- **yt-dlp needs a JavaScript runtime for YouTube**, and enables only `deno` by default — which nothing here ships. Without one it warns `No supported JavaScript runtime could be found … some formats may be missing`, falls back to a client it has already deprecated, and `--no-warnings` hides all of it. The core already runs on the bundled `node.exe` (v22.23.2, above yt-dlp's `v22 and up` floor), so `jsRuntimeArgs()` in `core/config.js` passes `--js-runtimes node:<process.execPath>` at both call sites — `extract.js` and `ytstream.js`. Deno keeps priority for a user who has one. The option exists since yt-dlp **2025.11.12**; `python/requirements.txt` pins a later build.
- **YouTube fallback** = the embedded player (`YoutubeItem`), used when the relay fails (private, age-restricted, no yt-dlp). Exact `[in,out]` looping then needs the **IFrame Player API**, not an `end=` embed, which loops back to 0: create the player, read `getDuration`, poll and re-seek to `in` when `out` is passed. The player replaces the div, so the wrapper keeps `pointer-events:none` and `width/height:100%`. Trim changes without recreating the player (read through a ref in the poll).
- **A YouTube card takes the ratio of its video, Shorts included.** The link is all that is known when the item is posed, so a `/shorts/` URL poses 9:16 and anything else 16:9. That is a hint, not the answer — a vertical video is just as often shared as a plain `watch?v=` link. The relayed stream is where the true ratio first appears (`videoWidth`/`videoHeight` on `loadedmetadata`), and the card is reshaped there around its own centre at constant area, which also repairs boards posed before the measurement existed. A proxy never feeds the measurement (its dimensions are the excerpt's), a cropped item is left alone (its box deliberately differs from the source), and the patch is not recorded in history — a measurement is not a user edit.
- Generic HTML pages exposing OpenGraph media or HTML5 `<video>`/`<source>` can stay linked or be downloaded according to the Board preference. They remain generic pages and do not become named settings providers.
- **Local videos**: `<video>` in WebView2 does not read `.mkv`. Route mp4/mov/webm to `/media` (Range, seek and loop work), everything else to `/stream` (remux, copy when the codec is native).
- **A local cut is played as a PROXY, not the raw file**: a cut (`trimOut` set) of a local file — often `.mkv`/HEVC — showed the **start of the file** because mid-file seeking fails over a stream copy, which reads as "wrong media". Such items play an mp4 proxy of the exact range (whole loop, no seek), regenerated on each mount (server cache), so nothing temporary is persisted.
- **Persistence** = `core/reference.js`: multiple scenes plus assets (pasted images written to disk, name = content hash). **SQLite via `node:sqlite`** when available, **JSON-file fallback** otherwise, same public API. Prepared statements are created **per call**: a retained `StatementSync` can be finalised by the GC, producing "statement has been finalized" on save.
- **Detachable window**: a second Tauri `WebviewWindow` (label `reference`, frameless, always-on-top) on the **same renderer** at hash `#reference`; `App.tsx` detects it and renders the board bare. Hand-off to that window goes through a reserved scene; `reference:push` pushes live additions. The detached window has **no toolbar and no icons** (requirement) — only a thin drag strip; every action is in the context menu. **In-place pinning**: on the Reference tab, when the main window is pinned, the panel renders the board bare in the same way, giving a floating board without opening a second window.
- **Autosave** is debounced into a reserved scene and restored at startup. It also silently rewrites a **named** scene. `save()` and `saveAuto()` both surface errors as a notice, with a single notice until the next success so a debounced burst does not spam. Notice auto-clearing is **centralised** in `setNotice` (error 5s, ok 2.6s, `sticky` for progress notices) — callers own no timers.
- **Text notes** (kind `text`): sticky notes, double-click to edit, **committed live on change** so text is never lost regardless of how editing ends. Default font is handwritten (Caveat, bundled). While editing inline, the inspector **stays visible** (style bar reachable mid-typing, PureRef-style): the textarea's `onBlur` only exits editing if focus does not move into that bar. For other item types the inspector hides during editing.
- **Frames** (kind `frame`) are containers: a discreet section panel with the title label as a tab **above** the top edge (the frame wrapper is `overflow-visible`, the others are `overflow-hidden`). Fill has 3 modes: none / tint / solid. A frame sits **at the back** (`z=0`, never brought to front on click) and **moving it moves the items it contains** (centre-in-rect test at commit).
- **Drawing is hand-made** (`DrawLayer.tsx`, kind `draw` = board-wide singleton, zero third-party dependency — Excalidraw was dropped for bugs and branding). Tools: select, pen, highlighter, line, arrow, rectangle, ellipse, diamond, eraser, plus colour, width, opacity steps, undo/redo. Shift constrains (15° angles, regular shapes). Shapes are stored in **world coordinates** and rendered in an `<svg>` transformed like the board layer, so ink scales with zoom; stroke width is stored in world units. Arrowheads are configurable at both ends; connector routing is straight / curved (quadratic control point) / elbowed. Hit-testing: bbox interior for closed shapes, proximity for pen and lines.
- **A pen stroke carries its own width, point by point** (`DrawShape.pw`, one factor per point, optional). Pressure — widened by tilt when that setting is on — is **baked in as the stroke is drawn**: changing a preference later never redraws existing ink. A variable width cannot be a `stroke-width`, which is one constant per path, so such a stroke renders as a **filled outline** (`penOutline`, ±radius along the local normal, round caps as arcs) in the three places ink is painted: the SVG layer, the canvas export and the SVG export. Hardware with no sensor reports a flat `0.5` (spec value), and a stroke where nothing ever varies drops `pw` entirely and stays a constant-width path — what a mouse draws. `pointermove` is read through `getCoalescedEvents()`: a stylus emits at 200–1000 Hz and the browser delivers one event per frame with the rest stacked inside it. The **eraser end** of a stylus (`button` 5 / `buttons` bit 32) erases whatever tool is selected.
- **Board performance — five levers, all measured**:
  1. Static shapes and their hit targets are `memo` sub-components keyed on `shapes` **alone** (not on the view), so N shapes are not reconciled per frame.
  2. The pan/zoom `transform` lives on a wrapper `<div>` (`will-change:transform`), **not** on the `<svg>`: a div is reliably promoted to a composite layer, while a transformed `<svg>` is not always promoted in Chromium and re-rasterised on pan — that was the perceived lag.
  3. **Imperative panning**: during the gesture there is **no** `setView` per pointermove (a 1000 Hz mouse would re-render the whole board per event). The view lives in a ref, applied in a coalesced rAF to the `[data-board-pan]` layers, with a single `setView` commit on `pointerup`. The dot grid is a dedicated div translated **modulo the step** (GPU composite, zero repaint; the old `backgroundPosition` re-rasterised the viewport every frame). Wheel zoom is coalesced to one per frame.
  4. **Spatial culling** (`useBoardCulling.ts`): past 40 items, only those whose bbox intersects the viewport enlarged by 75% are **mounted** (a board carries hundreds of media = as many decoders and layers). The zone is recomputed only when the viewport leaves it, never per pan frame; the selected or edited item is always mounted. A re-render during a gesture would restore the **stale** transform from the store, so a `useLayoutEffect` re-applies the live view before paint.
  5. **Fewer re-renders**: zoom is no longer a prop of items (read once at gesture start), content bounds are computed only when the placement frame is active, and image sequences preload a 24-frame window instead of the whole sequence.
- **Media picker** ("From the project") is a **right-docked panel with a transparent, unblurred overlay** and `modal={false}`, so the board stays sharp behind it. It accepts OS file drops, and its cards reuse the derush card mechanics (lazy thumbnail, hover preview, `content-visibility`) so they look and behave identically. Two modes: Browse (rush list → cuts of that rush, with on-demand detection if nothing is cached) and AI search (text query → nearest shots, thumbnails from the **shared** cache). Cards are draggable onto the board with a typed payload; the drop converts the cursor into board coordinates. **Thumbnails are lazy** (IntersectionObserver, `rootMargin:300px`): a rush with 1400 shots no longer floods ffmpeg.
- **Multi-selection**: marquee (left drag on the background; pan is middle-click or Space+drag). With ≥2 items selected the inspector becomes an arrange bar (align, distribute, grid, tidy, palette, grayscale, reset).
- **Pen tablets and touch screens are first-class** (`tabletInput.ts` + the Pen settings tab). Three machines want different things and the `auto` settings resolve them against a live probe (`matchMedia` + `maxTouchPoints` + whether a stylus has been seen): a display tablet next to a mouse, a tablet with no screen, and a touch-first machine with no wheel, no keyboard and no hover. **Two contacts pinch** — the gap sets the scale, the midpoint sets the translation, both relative to the frame captured at the second contact, so the gesture does not drift. Contacts are tracked in the **capture** phase on the board container: an item stops propagation to claim its own gesture, and a second finger lands on an item far more often than on the background. A pinch never steals a gesture already owned by an item (`navigating` held with no board gesture) and cancels a stroke in progress instead of drawing a second one. **Palm rejection** drops touch contacts while a stylus has been in play in the last 900 ms — the OS does it where the digitiser can, and the spec gives a page no way to opt out of or into that, so this is the net underneath. The **barrel button** can navigate instead of opening the context menu. Hover-revealed controls are the other half: Tailwind v4 wraps `hover:` in `@media (hover: hover)`, so on a pointer that never hovers such a control **does not exist**; the `hoverless:` variant (`src/index.css`) is that media query's other branch, and the Pen tab can force it on a machine that does hover.
- **Tidying is one action, not two** (`boardArrange.ts` + `store.tidy`): a layout (rectangle packing, grid, row, column) is combined with an optional size pass (same height / width / area) and applied in a **single history entry** — a plate is only tidy once its items are comparable. Everything measures the **rotated bounding box**, so an item at 45° is arranged on what it really occupies. Ordering is either the current one or natural by name (`shot_2` before `shot_10`). The packer is hand-written (free-space splitting, tallest first); no third-party dependency.
- **Snapping** (`boardSnap.ts`): while dragging or resizing, the moved box snaps to neighbouring edges, centres and corners, and sticks edge to edge with a configurable gap (0 = media touch). The threshold is in **screen pixels** (divided by zoom, so it never gets sticky when zoomed out), both axes are solved independently (hence corner snapping), **Alt suspends it for the current gesture**, and thin guides are drawn only while a gesture is running.
- **Palette extraction** (`palette.ts`): a selection of media is sampled as **displayed** (crop, mirrors and grayscale applied), aggregated across items **weighted by on-board area**, then quantised with `@material/material-color-utilities` (Apache-2.0, no dependency — Celebi quantizer in HCT space, plus scoring with the chroma filter disabled so muted tones survive). The result is a `palette` item posed on the board: swatches, click to copy the hex, regenerate from the source items.
- **Drawings can be bound to media** (`drawAnchor.ts`): on release, an arrow drawn from one image to another anchors **both endpoints**, and a stroke covering ≥80% of one item becomes owned by it. Anchors are stored as normalised coordinates in the item's own frame, so a linked drawing follows moves, resizes, rotations and mirrors — live during the gesture through `boardLive.ts`, which publishes geometry only when something is actually linked. A deleted item drops the anchor instead of leaving a ghost; the shape inspector unlinks (freezing world coordinates) or relinks.
- **Folder import** (`reference:scanFolder`): dropping a folder scans it recursively in the core and builds **one frame per folder**, tidied with the current settings, as a single undo entry. Items appear immediately at a provisional size; real ratios are measured in the background (6 at a time) and the batch is re-tidied without polluting history.
- **Board export** (`boardRender.ts`): PNG/JPG and SVG are rendered **from the model**, never by rasterising the DOM (a `<video>` and an iframe do not capture). One z-ordered pass paints images (current frame for video and sequences), text, frames, palettes and drawings — vector paths stay vector in SVG. Default size is the content plus a 3% margin, with a ratio-locked dialog; the same renderer produces the PNG that `Copy` puts on the system clipboard.
- **Cropping** uses a normalised `crop` on the item, displayed via an oversized media element plus translate; confirming adjusts the item ratio so nothing distorts. Images and videos both.
- **Shortcuts** (`useBoardShortcuts`): **all command shortcuts are rebindable**, combos included, through `prefs.shortcutKeys`; the handler matches a combo string to an action then dispatches. Drawing tool keys are rebindable too. Not rebindable ("Gestures"): arrows (nudge, step ÷ scale so pixels stay constant on screen, Shift ×10, burst coalesced into one undo), paste (browser event), pan, wheel, marquee, Shift constraints.
- **Board settings** is a non-modal floating panel with 5 tabs (Appearance / Media / Behaviour / Pen / Shortcuts) — a flat list of sections was interminable. The Pen tab ends on a **live hardware read-out**: hovering a stylus over the window fills in pressure and tilt without drawing, which is the only way to tell a disabled setting from a driver that exposes no sensor (Wacom with Windows Ink off reports a flat `0.5`). It is reachable from the home screen, the toolbar **and the context menu**, the last being the only route in pinned or detached mode. Preferences persist in `localStorage` and are shared by all scenes.
- **Right-click covers everything** (`BoardMenu.tsx`): `onContextMenuCapture` selects the item under the cursor (or deselects on empty space) **before** the menu opens, so the menu is adaptive — item actions when an item is targeted, then always the board actions.
- **Tooltips**: every icon button goes through the custom `Tooltip` wrapper; native `title=` is never used. Colour pickers are wrapped in a `TooltipTrigger render={<span/>}` so the picker's own popover trigger stays inside.
- Media elements are `display:block` (`<video>`, `<img>`, YouTube iframe) to avoid the thin horizontal line from inline baseline gaps during playback.

## Cut flow (`src/components/rushes/`)

A **flow** is a run of clips opened together in one scrolling grid. Opening a single clip opens a
flow of one: `useShotDetection` always takes a list of paths, so a four-clip grid is the same code
with four entries rather than a mode of its own. Selecting clips in the browser and pressing
**Flow** opens them; the store keeps the run in `flow` and its first clip stays `selected`.

The whole point is that scrolling a flow is indistinguishable from scrolling one clip. What that
costs, and therefore what must not be broken:

- **Every clip is published at once.** The caches of all clips are read in parallel and posted by a
  single `setSegments`. A clip appearing mid-scroll would move what the user is looking at.
- **Shot order is flow order, never a global sort.** Each clip has its own seconds, so sorting the
  grid by `in` would interleave them. Merging reinserts the union at the place of the first shot it
  absorbed instead of re-sorting.
- **Every shot carries its `path`** (`Segment.path`), and every card, preview, thumbnail and export
  target resolves through it. It is absent only in single-clip grids, where the view's path stands in.
- **Editing stays inside one clip, selection does not.** A selection crosses the flow because it
  feeds export; a merge groups by file and records one union per clip, since two shots from
  different files share no bounds. Cut edits are stored per (clip, model); undo/redo snapshots the
  whole table, so one Ctrl+Z undoes the last gesture wherever it happened.
- **A timeline build carries one source file**, so a flow chains one call per clip: the first sets
  the target, the rest append to the timeline it returned.
- **Clips with no shots yet are named, not hidden** — the toolbar offers to cut only those, leaving
  the already-cut ones untouched (`detect(only)`), because a silently missing clip reads as a grid
  that simply ends early.

`cutFlow.ts` derives where you are from the scroll offset and the grid geometry alone — no per-card
observer, and one read per frame rather than one per scroll event. `CutFlowNav` owns that position
and is **the only thing in the page that reacts to scrolling**: it names the clip currently at the
top of the grid and jumps to any other. Keeping the index in `CutStudio` instead re-rendered the
whole studio at every clip boundary, rebuilding the grid's several hundred cards exactly while
scrolling. Its label must pass the clip name to `SelectValue` explicitly — Base UI renders the raw
value otherwise, which showed the index instead of a name.

## `.netsu` container

`core/netsu/`, façade `core/netsu.js`. The share and project format is a **SQLite container**, no longer a ZIP.

- A file written in one shot cannot be the source of edits. Here items are **one row each** (`board_items`) and media bytes are **content-addressed and chunked** (`blobs`/`blob_chunks`, 8 MiB) — `node:sqlite` exposes no incremental blob API, so a multi-gigabyte medium never passes through memory whole.
- `db.js`: `page_size=8192` **before** the first write, WAL, `synchronous=NORMAL`, `rev` incremented per transaction, `seal(dest)` = checkpoint + `VACUUM INTO` (**never** `VACUUM` on the open database). Export writes a `.part` **inside the target folder** then renames (atomic on the same volume), so a half-written `.netsu` never exists.
- **The type is decided by the first bytes** (`sniff`: `SQLite format 3\0` vs `PK\x03\x04`), not by the extension: v1 ZIP archives already sent out stay importable (read-only legacy path).
- **"Save as" makes the `.netsu` the WORKING DOCUMENT** (`core/netsu/{session,project,sidecar,recents}.js`, tested). Sharing and saving are different operations and do not share code: sharing builds a **self-contained** file in one shot with re-encoded media; a project rewrites the **same** file a hundred times. Four rules:
  1. **The file stays OPEN** (session registry keyed on the resolved lowercase path — two spellings of the same file on Windows would open two databases on one file). Two caches live there for the same reason: content identity per path (otherwise every save re-reads the first megabytes of every rush) and last JSON written per item.
  2. **Incremental writes, compared on the item's JSON**: a thousand-item board with one moved item writes one `UPDATE`, and a save with no change writes **zero** rows (locked by test). That is the reason for the row-per-item schema.
  3. **No re-encoding**: a project only **references** rushes. The share path re-encodes per medium, which would mean tens of seconds per save.
  4. **Companion folder `my-project.medias/`**: whatever has no home of its own on disk (a pasted image, a medium fetched from a link) used to live in the **global** asset store shared by every board, so a project saved elsewhere left its media behind and clearing the store broke unrelated projects. The token path is **relative** to the `.netsu`, the only form that survives a move, and the pair moves together. The folder is **browsable**, so it is sorted: `images/`, `videos/`, one folder per image sequence under `sequences/`, `other/` as a fallback, and each file is named after its board item with a 12-hex content suffix (`aurora-2f4a70a71de8.jpg`) — that suffix is what keeps deduplication free. A save **never moves an already-sorted medium**, even when its item was renamed: a Ctrl+S must not churn the folder. A project written in the older flat layout is sorted on its next save by **renaming**, never by copying bytes. A media adopted from another project's companion folder (that is, "Save as") moves into the new one, so the copy does not stay tied to the original. A `..` in a received token cannot escape the folder, and orphan cleanup — which also prunes emptied sequence folders — is **suspended when a save empties the document at once** — that is almost always a board that has not loaded yet, and bytes do not come back.
- **Nothing a save deletes can still be needed.** Cleanup is the only step that destroys bytes, so three things feed its keep list. The **media held before an upscale** (`prevMedia`) is tokenised and adopted like any other project medium — otherwise the "undo upscale" button pointed at a file the same save had just erased. The board sends `retain`, the durable locators its **undo history** still holds: autosave fires 500 ms after a deletion, and without that list Ctrl+Z brought the item back without its pixels. Finally **saves are serialised per file** (`queued` in `core/netsu.js`): a save that copies a rush outlives the next autosave tick, and two concurrent passes would let the older one's cleanup erase what the newer just adopted.
- **A project does not pay twice for the same medium.** Blobs are cleaned like companion files: bytes no room references leave, and `PRAGMA auto_vacuum = INCREMENTAL` (set at creation) returns the freed pages. Opening a shared file as a project copies its media into the companion folder, so keeping the embedded originals would double the file for good. Copying and hashing large media run **asynchronously**, one chunk per transaction (`putFileAsync`, `adoptAsync`): the core is single-threaded, and a synchronous multi-gigabyte copy froze previews, the media server and every other module for the duration. Sharing reports its progress item by item over `netsu:progress`.
- **A shared file describes media, never machines.** Export writes `media.path` empty: an absolute path means nothing on the recipient's disk and publishes the sender's session name and disk layout, while relocation works on name + size + head fingerprint. `prevMedia` is reduced to its **origin link** if it has one and dropped otherwise — its bytes live with the sender, embedding them would double the weight for a version nobody looks at. Missing media relocate **in bulk** (`netsu:relocateFrom`): one folder, every medium recognised by name and size, and homonyms of equal size are never guessed.
- A board bound to a file **leaves** the internal library (`sceneId: null`): two copies of one board would diverge. After "Save as" succeeds, the file recent records the converted internal scene id, then removes that scene; the id remains a de-duplication guard if cleanup must be retried. NetsuBoard renders session, file projects, and unconverted scenes in one **Recent** grid. The recents registry otherwise stores file addresses, filters missing files **on read** and never rewrites, so a project on an unplugged drive is not forgotten forever. A v1 ZIP archive opens **read-only** rather than being refused; "Save as" converts it.
- **The global asset store is swept at boot** (`refStore.sweepAssets`, `NR_HOME/reference/assets`). It receives everything the app makes for a board — pasted images, fetched media, extracted frames, **upscale outputs**, hundreds of megabytes per shot — and nothing ever left it. A file goes only if no library scene references it (item refs, sequence frames, `prevMedia`, `localMedia`) **and** it is older than the 14-day grace period. It runs at startup and only there, because a board opened from a `.netsu` still points at that store in memory. Board upscales also go through `core/upscaleLedger.js` now: same source, same bounds, same settings returns the file already produced instead of paying for the GPU again.
- **Media embed levels** (`core/netsu/levels.js`, pure, tested): `link` (poster only) · **`preview` (default, the played range re-encoded)** · `margin` (widened range so bounds stay adjustable without the original) · `full`. Quality and margin are settings. **Do not produce embedded media through `proxySegment`**: it caps duration at 4s for looping previews — `core/netsu/embed.js` reuses the encoding building blocks without that cap or the playback queue. `netsu:weigh` estimates the weight of all four levels without encoding anything. An abnormally long range is **reported, never silently trimmed**.
- **The notebook is a `.netsu` document too** (`core/netsu/notebookDoc.js` + a router in `core/notebook.js`, tested). SQLite was chosen for the **access pattern**, not the file size: the notebook saves **as you type** (700 ms debounce) and one keystroke touches **one** page, whereas the ZIP re-serialised the whole page index and recompressed it at every pause, and had to be fully decompressed to open a single page or search a word. `sqliteBackend` takes a **handle** instead of a path, so the same tables and queries live either in `NR_HOME` or in a container. `createNotebookStore` became a **router**: channels do not all carry the target notebook, so routing uses the most precise id available and otherwise asks each store which one owns the object — a primary-key `SELECT`, never a scan. Files come **before** `NR_HOME`: after "Save as", the file is the truth. Three points hold: the notebook **keeps its id** when moving (otherwise its pages, mentions and subpages point at a vanished notebook), the trash follows, and the original copy is removed from `NR_HOME` only **after** verifying the number of pages written (a full disk must not leave the user with no notebook at all). Media go to the companion folder — **flat, at its root**, since a notebook token carries a file name and no path — and their URLs are stored as **tokens** (`core/netsu/mediaTokens.js`): a block URL carries an absolute path and a port, neither of which survives moving the project or restarting the core on another port. The renderer supplies its URL template on open — only it knows its base and token.

## Voice module (`src/components/voice/`)

Word-level transcription, silence removal, SRT/VTT subtitles, text-based editing. **Not verified at runtime** (needs a GPU, models and Resolve for the timeline).

- **Engines**: ASR `whisper-turbo` (faster-whisper large-v3-turbo, reliable word timestamps) or `parakeet-v3` (via **onnx-asr**, not NeMo/transformers; defensive result parsing). VAD segmenter is **Silero v5 only**.
- **NOVA-VAD is not a segmenter** (it is a file-level speech/noise classifier with no fine boundaries) and is used as a **confirmation layer** above Silero: short speech regions (< 1.5s) are re-classified and dropped when judged non-speech with enough confidence (coughs, keyboard, noisy rushes). ⚠️ **No public weights exist** for it, so the toggle is inert until they are trained locally; degradation is graceful (Silero alone). Its `requirements.txt` must **never** be installed (it pins torch/torchaudio/pyannote versions that would break the venv) — only its feature extractor is imported, which needs no torch.
- **The word-timestamp contract is backend-agnostic**: `{start,end,word,conf}` in seconds. Seconds→frames conversion happens **only** in `buildTimeline`, so the three timeline invariants are reused untouched and no new timeline channel exists.
- **Silences are refined AFTER the model** (`nrvoice/vad_silero.py`): Silero places boundaries, energy corrects them — `snap_ms` (snap to the nearest RMS trough so the cut lands in real silence), `noise_gate` (drop **short** regions that are too quiet: keyboard, mouth clicks; never beyond 0.8s, which would be soft speech), `pad_end_ms` (end margin distinct from the start one, applied by us and not by Silero, so the order gate → snap → pad is guaranteed). On the JS side, `guardWords` forbids any boundary from landing in the middle of an ASR word. These layers are independent from the presets.
- **Filler detection**: no usable multilingual filler model exists (`whisper-timestamped` is AGPL, CrisperWhisper is CC-BY-NC), and Whisper does **not** emit hesitations — it is trained to produce clean text. Two routes: a **verbatim** transcription (an initial prompt seeded with fillers per language makes them appear) and an **acoustic** detector (flat F0, low spectral flux, stable RMS, low ZCR, duration 0.18–1.2s, thresholds calibrated on the clip, plus **LPC formants in the schwa region** whose roots must be filtered by **bandwidth < 400 Hz**, otherwise a systematic false F2 appears). Restricted to inter-word gaps and low-confidence words — a full scan flags sustained end-of-sentence vowels. Overlapping detections combine probabilistically, and a span close to a pause gains confidence. Always **strikeable suggestions, never an automatic cut**.
- **Home screen is a folder tree plus batch**: the tree comes from `buildClipTree` (`components/rushes/libraryShared.ts`), the **single** source shared with the derush browser, so a rush is in the same place everywhere. Dense rows use `content-visibility` and memoise on primitives only, so a progress frame re-renders **only** its row.
- **Batch rendering follows the export profile**: the selection is rendered with the active profile (`timeline_import` builds one timeline per rush, otherwise one merged file per rush in a folder asked for once), analysing clips on the fly, `RENDER_CONCURRENCY` rushes at a time, cancellable. Progress is routed by `jobId` (the rush path) so several renders in flight no longer steal each other's bar.
- **Playback**: skipping cuts runs in a **rAF loop** that jumps **40 ms before** a kept segment's boundary, because `timeupdate` only fires at ~4 Hz and the start of each cut was audible. Playhead and current word refresh at ~15 Hz in the same loop rather than re-rendering the cut list at 60 Hz.
- Runtime traps, all measured: `pip install silero-vad` pulls the **latest** torchaudio and breaks a pinned torch (`WinError 127`) — pin torchaudio to the installed torch; faster-whisper on GPU needs `site-packages/nvidia/{cudnn,cublas}/bin` added to the DLL search path, otherwise it silently falls back to CPU; with onnx-asr the **word boundary is a leading space**, not `▁`; read WAV through `soundfile`, not torchaudio; and `extractAudio` must dedupe in-flight calls, since two parallel analyses raced on the same temporary file.
- Base UI gotchas: `Slider.onValueChange` passes a **number** during a mouse drag (an array only from the keyboard), so always `Array.isArray(v) ? v[0] : v` — the `&&` form freezes the slider; and never wrap a `ToggleGroupItem` in a `Tooltip`/`<span>`, which breaks selection (put the hint in a caption under the group).

## Model catalog (`src/lib/modelRegistry.ts` ⇄ `core/models.js`)

The renderer registry and the core manifest declare **exactly the same ids** (locked by `test/model-catalog.test.cjs`). The registry holds what the user reads (label, licence, VRAM, size); the manifest holds what the core downloads (URL/HF repo, pip, vendor).

- **`advanced: true` means "outside the current selection".** The models page shows only non-advanced entries by default: **1 to 5 per task**, each covering a **different** situation, never two variants of one network. An "Advanced" button reveals the rest, with a count. An advanced model that is **already installed stays visible** — otherwise you could not remove it without guessing where it hides. A `default` model is never advanced.
- **`available: false` means the Python engine is missing** → the entry stays in the catalog as a roadmap item but is neither downloadable nor selectable. A silent entry beats several gigabytes that will produce no image.
- **One capability, one entry.** A component that carries both a binary and non-redistributable vendor DLLs is a **single** entry with an `sdk` field: each half is useless alone, and two rows would offer not a choice but two ways to fail.
- **Labels use the name published by the repo that ships the weights**, even when that repo only reuses another's checkpoints.
- **`kind: 'pipfork'` + `exclusive` marks models that REPLACE a shared package.** Training-free methods published as forks of the same pip distribution are mutually exclusive; only one can occupy the slot. The provider is detected by a **fingerprint inside the installed package**, never by a state file that a manual `pip install` would falsify. Installing uninstalls first, requires at least one matching weight, and **removal puts the original package back** (otherwise the weights remain but nothing can load them). The catalog says so **before** the click (badge + section banner). `pipSubdir` covers a package that is not at the repo root, since a tarball URL cannot target a subfolder (pip's `#subdirectory=` requires git).
- **Upstream pip dependencies must never be resolved blindly.** Some models declare their **demo's** dependencies (Gradio, PySide6, tensorboard, a `git+` dependency that fails without git) and **exact pins** of shared libraries: installing them downgrades the shared venv — that is where pip's "dependency conflicts" message comes from — for a gigabyte of code that never runs. Install with **`--no-deps`** and declare what inference actually imports.
- **`--no-deps` does NOT protect against an exact pin: it must be removed from the pyproject.** The pin survives in the **metadata** of the installed package and pip honours it on every later resolution, silently downgrading a dependency under the whole venv. Measured: a model pinning `huggingface_hub==0.36.2` broke a transformers import chain, so **object removal failed with an error that never named that model**. Two guards, both locked by test: a patch that strips the pin, and an explicit floor in the declared dependencies. General rule: any `==` pin on a **shared** dependency must be removed by `pipPatch`, never merely bypassed with `--no-deps`.
- **Benchmark submissions belong in advanced**: ×4 models trained on clean bicubic degradation have no effect on noise or compression and no video track record; presenting them next to production restorers misleads.
- **Model-driven upscale settings** (`modelCaps` in `upscaleShared.ts`, mirroring the Python side): `native` marks the network's own factor (starred in the picker, with an explicit note that another factor is resampling, not better reconstruction), and `tuning: "onnx-window"` hides tile/pad/precision on a fixed-shape ONNX graph where only the overlap matters. A slider with no effect reads as a broken setting.
- Before adding a model: probe its source (a script checks every network source in the manifest by real request), confirm its Python engine exists, and file it as advanced **by default** — the current selection only grows when a situation is not already covered.

## Process hub output (`src/components/upscale/` + `core/imageOutput.js` + `python/upscaler/imgout.py`)

Every op of the hub (upscale, interpolation, depth, cutout) writes one of three things: a video, a
still image, or a numbered image sequence. One contract carries that choice from the settings panel
down to the sidecars.

- **A still source can only write an image.** `isStillSource` decides on the extension, and the
  output selector is then locked on "Image" — a video codec has nothing to encode. **The animated
  GIF is deliberately NOT a still**: it goes down the video path so it keeps its frames instead of
  collapsing to its first one. Interpolation is disabled outright on a still-only selection: it
  needs two neighbouring frames, and running it would produce a job that can only fail.
- **A sequence always lands in its own folder**, and it is that **folder** that is imported to the
  Media Pool — Resolve accepts an image sequence by its folder, never by a `%06d` pattern. Hundreds
  of frames next to the videos would also make the output folder unusable.
- **The ffmpeg image arguments are resolved ONCE, in the core** (`core/imageOutput.js`), and travel
  in the request as `image_args`, exactly like `video_args` for the codecs. The Python side keeps an
  identical fallback builder for direct CLI calls, and nothing else re-derives that mapping.
- **PNG compression is lossless at every level** (only write time and file size change), so the
  level is presented as a speed choice, not a quality one. **16-bit only means something when the op
  produces more than 8 bits**: the depth map writes real 16-bit grey through cv2, everything else
  stretches 8-bit (×257) and says so. JPEG carries no alpha, so the cutout never offers it.
- **RTX VSR refuses an image output** instead of being swapped for another engine: its CLI only
  writes MP4, and the user picked RTX on purpose.
- **A chain forces `outputKind: 'video'` on every step**, including the last: each step feeds the
  next one a file it must be able to read, and a frozen step setting must not break that.

### Output naming (`outputNaming.ts`)

- **One pattern names the whole batch**, resolved at launch: `{name}` `{op}` `{scale}` `{model}`
  `{date}` `{n}`/`{nn}`/`{nnn}`. The default `{name}_{op}_{scale}` reproduces the file names the hub
  produced when the suffix was hard-coded in the core, so the change is invisible until it is used.
  An **empty token collapses its separator** — `clip_depth_` is a dirty name.
- **A rename lives on the source, not in a side table** (`UpSource.outName`): it is set by renaming a
  media in the selection tray, survives an op or page switch with the tray, and takes precedence over
  the pattern. There is no per-media list of controls in the settings panel — the pattern covers the
  batch, a rename covers the exception.
- **Two sources landing on the same name are named out loud, before the run.** The second output
  would silently overwrite the first, so the collision is reported with the offending name, marked on
  the guilty rows of the tray, and repaired in one click by adding a counter to the pattern. The
  comparison is **case-insensitive**, like the file system underneath.

## Roto Studio (`src/components/netsulab/roto/` + `core/roto.js` + `python/nrroto/`)

Interactive SAM segmentation: include/exclude points on multiple objects → immediate mask → propagation → fine matte, alpha export, object removal. Ideas taken from Sammie-Roto-2 (**GPL-3.0 — ideas and UX only, never its code**) and reimplemented.

- **Two engine generations, one interface.** `nrroto/sam_engine.py` (SAM 2.1 and its forks) and `nrroto/sam3_engine.py` (SAM 3.1) expose the same methods; `session.py` chooses on the **model id**, not on the weights folder — a folder does not state its generation. The id therefore travels from the renderer to Python next to the weights path. Switching generation releases the old engine first.
- **SAM 3 does not speak SAM 2's API.** Where SAM 2 returns an inference state the caller carries around, SAM 3 owns its sessions and is driven by requests (`start_session` / `add_prompt` / `reset_session` / `close_session`, and a streaming request to propagate). Its masks arrive already full-resolution and boolean, not as logits. Two upstream traps: points are passed in **pixels** with `clear_old_points: false` (we resend the full point list every call), and its video predictor calls `.cuda()` unconditionally — there is **no CPU path**, so refuse explicitly instead of surfacing a torch traceback.
- **A SAM 2 fork that keeps the API needs no extra code**; only its Hydra config path changes, switched as soon as the installed package contains it — otherwise you would install the fork and silently get plain SAM 2.1.
- **Persistent Python session** (`roto.py serve`, JSON-lines, one job at a time) with a **disk cache** keyed on `sha1(path|mtime|size|in|out)` holding frames, mattes and points (LRU 6). Reopening a rush is instant, points **and** tracking restored. `close()` no longer deletes the folder.
- **Extraction runs in a THREAD**: `open` answers on the first frame (`ready:false`, frame count estimated), ffmpeg extracts with `-start_number 0` (0-based directly, no renaming), and the end is signalled so the total can be corrected. The frame viewer retries a 404 frame after 400 ms. SAM waits for extraction to finish, since it scans the folder once.
- **Propagation**: `all` wipes mattes and runs forward and backward from every annotated frame (covering frames **before** the first point, unlike SAM 2's forward-only default); `forward`/`backward` re-propagate **partially** from the current frame, keeping existing mattes; `count` gives **step-by-step** tracking. `STAGE:prog:cur/total@frame` makes the playhead follow the tracking live, **and the union matte just written is displayed live** by serving `work/mattes/union/%05d.png` over `/media` and tinting it with CSS `mask-image` + `mask-mode:luminance` — zero requests to a busy daemon. Cancellation writes a `cancel.flag` **outside** the daemon queue, so the Python sink stops cleanly and keeps the frames already written.
- **The live matte is arbitrated by an increasing SEQUENCE number, not by the current frame.** At ~7 images/s the next matte is requested before the previous one finishes loading, so a `frame === current` test in `onload` discarded **every** load and the mask stayed frozen through the whole tracking pass. Corollary: the tinted overlay is cleared on the first frame event — it is stale, the daemon is busy so nothing will refresh it, and leaving it drawn showed a motionless mask over advancing tracking.
- **Step-by-step must stop deterministically in the sink** after `count` **new** frames: `processing_order` **includes the starting frame** (re-emitted), so relying on `max_frame_num_to_track` is not enough.
- **Non-destructive post-processing** (`nrroto/postproc.py`): grow, feather, hole filling, speck removal, border fix, contour smoothing, alpha gamma — applied to the overlay at render time and **baked only at export**. The propagated PNGs never change. cv2 (headless) with a PIL/numpy fallback.
- **Automatic ROI** (`nrroto/roi.py`): union bbox of the mattes +10% **plus the erase margin ×2** (otherwise, on a small object, the ROI contains neither the dilated mask nor the seam ring), snapped to 8 (16 for diffusion), skipped past 90% coverage. Fine matte and removal then process only the useful area, with the alpha pasted back into full-frame PNGs. **Removal composites the generated result only inside the dilated, softened mask**; the rest stays the untouched original.
- **Never call the upstream package's `process_video()` for fine matting — it is a DEMO.** It stacks the whole sequence in RAM (~8 GB for 1000 1080p frames) and then encodes the alpha as **8-bit h264 mp4**, destroying exactly the edge detail the model just computed. `nrroto/matte.py` drives `InferenceCore.step()` frame by frame and writes **one grey PNG per frame and per object**. Four points hold:
  1. **Seed on ANNOTATED frames** (their mask was validated), not on the first matte available: plan a backward pass from the first seed to the start, then a forward pass per seed. Each direction re-establishes memory, so the first seed is the **only** frame processed twice. Locked by `test/test_roto_matte.py`.
  2. **The reset between segments IS `first_frame_pred=True`** (N stabilisation passes after `step(image, mask)`): that flag resets the internal counter and clears temporary memory **inside** `step`. Do not add an external purge — the full clear would also wipe the sensory memory upstream deliberately keeps.
  3. **The image is normalised `/255`, the mask is NOT** (raw 0..255). That is what the reference implementation does; dividing the mask changes the seeding regime.
  4. **`max_internal_size` is the NATIVE mechanism** of `step` (downscale, pad to a multiple of 16, restore size). Resizing yourself doubles the resampling.
- **Two families of fine-matte engine, one interface.** One seeds on a few validated frames and propagates memory; the other (`nrroto/videomama.py`) propagates nothing — it re-estimates a **batch** of frames at once, guided by each frame's mask, so its settings are batch size and overlap. Four upstream contract points not to "fix": CLIP conditioning is **null** (the UNet was fine-tuned with zeroed encoder states); a **single** denoising step at `timestep=1` (the model is distilled for it, looping a sampler degrades); the input is `cat([noise, image, mask])` on the **channels**, in **raw** latents (only the **output** is divided by the scaling factor — getting the side wrong gives a plausible but wrong image); and dimensions must be multiples of 8 or the VAE does not reconstruct. At a batch junction two mechanisms stack: the next batch receives the previous **soft alpha** as its mask, then the two predictions are blended linearly. Its weights are **split across two repos**, hence selective download flags, so you do not pull gigabytes for one VAE.
- **The fine matte lives BESIDE the tracking mattes** (`mattes_refined/`), never in their place, and a toggle switches without recomputing. `_matte_root()` is the **single** arbiter of which source is authoritative, consumed by the mask, the post-processing and the removal — without that single point, preview, export and removal end up disagreeing. Any re-propagation **invalidates** it: an alpha computed from rewritten mattes would be a lie. Multi-object union is a **per-pixel maximum**, not a binary OR.
- **The chain used to be BINARY end to end** (mattes written 0/255, loads thresholded at `> 127`), so a soft alpha was destroyed even when reinjected. Hence the soft path: load alpha without thresholding, and post-process where hole/speck decisions are **made** on `> 127` but **written** into the alpha; grow is dilate/erode on the grey; smoothing is morphological opening then closing, never blur followed by re-thresholding.
- **Object removal without a visible trace.** The erased area used to give itself away by colour, softness and missing grain. Chain shared by both engines:
  1. **Clean plate** (`nrroto/cleanplate.py`): the hidden background is first looked for in **neighbouring frames** (global motion by Shi-Tomasi + Lucas-Kanade + RANSAC similarity outside the mask), warped, then combined with a **low median** of the candidates — a passer-by stays a minority, and a low median returns a **really observed** value, therefore real grain rather than an average. Motions are estimated between **consecutive** frames and then composed; estimating each pair would cost N·K tracks instead of N. The model then only receives the **residual**. With a static camera and a static object, coverage is 0 and the pass **switches itself off** after 6 frames rather than paying for a useless track.
  2. **Seam harmonisation** (`nrroto/harmonize.py`, tested): a low-frequency bias field by **normalised convolution** `blur(diff·w)/blur(w)` (the "lighting correction" idea without a Poisson solver; the field equals the real edge difference, so there is no seam), a temporal EMA to stop flicker, a sharpening gain that equalises high-frequency variance on the ring, then **measured grain** (robust σ by MAD, size by autocorrelation, amplitude modulated by luma, **seed = frame index** because real grain is temporally decorrelated). All measured, nothing invented, so it is a no-op on a clean source.
  ⚠️ **`harmonize()` receives the engine's RAW output, never an already-composited image**: the bias is measured **around** the hole, where truth is known. Compositing the reference into the generated frame before the call cancels the measurement and the correction becomes zero (real bug, caught by the test).
- **The mask sent to the diffusion model is HARD.** The vendored pipeline binarises then dilates by a fixed iteration count, so passing it the **softened** mask erased the whole gradient tail **plus** that dilation at model scale, and the regenerated area no longer matched the requested margin. Pass one iteration and dilate yourself at full resolution — **never `0`, since `binary_dilation(iterations<1)` dilates until saturation**. Also: round with `+0.5` on output (truncating darkened the generated area by half a level), pad by reflection to a multiple of 16 instead of resizing twice when the ROI already fits, resolution steps with **automatic VRAM fallback**, and stream the encode instead of stacking every frame in RAM.
- **Diffusion windows OVERLAP** (default 81 frames, 8 overlapping). Disjoint, each block was diffused with its own noise and the junction showed as a jump every 81 frames. Each window **withholds** the frames shared with the next one and writes them only once blended — without that hold, the overlap would produce duplicate frames. Exact coverage is verified by test.
- **Model settings are not mask settings.** `seed` (default 42) makes sampling reproducible: without an explicit generator, two identical runs gave two results, so you could neither replay a good fill nor retry a bad one identically. Window and overlap trade temporal coherence against VRAM; VAE tiling (which leaves seams, to be turned off when VRAM allows) and CPU offload trade speed for memory. The model-side dilation constant stays at 1 and is not exposed.
- SAM 2 runs under **bf16 autocast** (CUDA Ampere+) around init/add/propagate, with the upstream CPU offloads unchanged.
- **The right rail is a five-step accordion** — Selection (SAM model · objects · points, all describing one thing) · Tracking · Display · Mask (fine matte **then** retouching, in the order they apply) · Output. Nine scattered drawers held the same settings. A **closed** drawer shows its state ("SAM 2.1 Hiera Base+ · 1 object", "12 steps · seed 42"): without that summary, folding hides information instead of saving space. Counters use i18next plurals.
- Three display traps, all hit for real: (1) the `accordion-down/up` keyframes shipped by tw-animate-css target CSS variables that **do not exist** under Base UI, so the cascade fell back to `height: auto`, which fought the measured height and made the whole panel shake — **height animation is removed** (it reflows every frame, which this app refuses near video decoding) and state is carried by the chevron; (2) `scrollbar-gutter: stable` on the container, otherwise a scrollbar appearing reclaims ~15px and recomposes the column on every click; (3) hover underlined titles by default, moving a 36px row's baseline — replaced by a background.
- **Viewer**: wheel zoom 1×..8× centred on the cursor, middle-click/Alt pan, double-click reset (CSS transform; normalised coordinates are read on the transformed rect so point placement is unchanged). Shift+hover previews the candidate mask through a temporary point, reverted by replay, debounced 150 ms. The timeline is a custom scrubber: a 12-thumbnail filmstrip built from the **already extracted** frames served over `/media` (zero ffmpeg), colour markers for annotated frames, in/out handles with the out-of-range area dimmed.
- **The overlay is never fetched while the daemon is busy** (it is serial — the queue would explode); live tracking goes through the `/media` matte instead.
